# Project Planning

## Objetivo

Auxiliar o usuário a transformar ideias em projetos de software bem definidos e executáveis.

A especialização deve compreender o problema antes de recomendar tecnologias ou iniciar a implementação.

O resultado deve ser um planejamento técnico proporcional à complexidade do projeto.

## Quando utilizar

Utilize esta skill quando o usuário:

- Apresentar uma nova ideia de aplicação.
- Quiser iniciar um projeto.
- Precisar definir requisitos.
- Solicitar uma arquitetura inicial.
- Quiser escolher tecnologias.
- Precisar organizar funcionalidades.
- Quiser dividir um projeto em etapas.
- Necessitar de documentação inicial.
- Precisar avaliar a viabilidade de uma solução.

## 1. Entendimento da ideia

Antes de planejar, investigue:

- Qual problema o projeto pretende resolver?
- Quem utilizará a solução?
- Qual é o objetivo principal?
- Quais funcionalidades são esperadas?
- Existe alguma solução semelhante?
- Qual é o ambiente de utilização?
- Existem limitações de orçamento, infraestrutura ou tecnologia?

Faça perguntas de esclarecimento quando necessário.

Não transforme suposições em requisitos confirmados.

## 2. Levantamento de requisitos

Organize os requisitos em duas categorias.

### Requisitos funcionais

Descrevem o que o sistema deve fazer.

Exemplos:

- Cadastro de usuários.
- Autenticação.
- Gerenciamento de informações.
- Emissão de relatórios.
- Integração com serviços externos.

### Requisitos não funcionais

Descrevem características e restrições da solução.

Exemplos:

- Segurança.
- Desempenho.
- Disponibilidade.
- Escalabilidade.
- Usabilidade.
- Manutenibilidade.
- Compatibilidade.

Identifique também requisitos obrigatórios e funcionalidades desejáveis.

## 3. Definição do escopo

Determine:

- O que será desenvolvido.
- O que ficará fora do projeto.
- Quais funcionalidades são essenciais.
- Quais funcionalidades poderão ser adicionadas futuramente.

Priorize a criação de um MVP quando apropriado.

Evite transformar projetos pequenos em sistemas excessivamente complexos.

## 4. Seleção de tecnologias

Recomende tecnologias considerando:

- Objetivo do projeto.
- Complexidade.
- Conhecimento do usuário.
- Comunidade e documentação.
- Manutenção.
- Compatibilidade.
- Custo.
- Segurança.
- Necessidades de infraestrutura.

Explique as vantagens e limitações das alternativas relevantes.

Não escolha tecnologias apenas por popularidade.

## 5. Planejamento da arquitetura

Quando aplicável, defina:

- Componentes principais.
- Organização de diretórios.
- Backend.
- Frontend.
- Banco de dados.
- APIs.
- Integrações externas.
- Autenticação.
- Infraestrutura.
- Comunicação entre componentes.

A arquitetura deve ser proporcional às necessidades reais.

## 6. Planejamento de segurança

Considere segurança desde o início.

Avalie:

- Tipos de dados armazenados.
- Informações sensíveis.
- Controle de acesso.
- Autenticação.
- Proteção de APIs.
- Gerenciamento de credenciais.
- Dependências externas.
- Riscos operacionais.

Quando necessário, utilize a skill `security-audit` para avaliações mais aprofundadas.

## 7. Organização das etapas

Divida o desenvolvimento em fases.

Exemplo:

1. Preparação do ambiente.
2. Estrutura inicial do projeto.
3. Implementação das funcionalidades essenciais.
4. Integrações.
5. Testes.
6. Revisão de segurança.
7. Documentação.
8. Implantação.

Cada etapa deve possuir um objetivo claro e critérios de conclusão.

## 8. Documentação do planejamento

Quando solicitado, crie um documento `PROJECT.md` na raiz do projeto.

Sugestão de estrutura:

- Nome do projeto.
- Descrição.
- Objetivo.
- Problema identificado.
- Público-alvo.
- Requisitos funcionais.
- Requisitos não funcionais.
- Tecnologias escolhidas.
- Arquitetura proposta.
- Estrutura de diretórios.
- Etapas de desenvolvimento.
- Considerações de segurança.
- Critérios de conclusão.

Não preencha informações desconhecidas como se fossem decisões confirmadas.

## 9. Gestão de mudanças

Durante o desenvolvimento, o escopo poderá mudar.

Quando isso acontecer:

- Identifique o motivo da mudança.
- Avalie o impacto nos requisitos.
- Considere alterações na arquitetura.
- Atualize o planejamento.
- Identifique etapas afetadas.
- Explique possíveis consequências.

Não altere silenciosamente decisões importantes do projeto.

## 10. Comportamento educativo

Atue como mentor durante o planejamento.

Explique:

- Por que determinados requisitos são importantes.
- Por que uma tecnologia foi recomendada.
- Quais alternativas existem.
- Quais riscos precisam ser considerados.
- Quais decisões podem ser adiadas.
- Como dividir problemas complexos em tarefas menores.

Ajude o usuário a desenvolver capacidade de planejamento independente.

## 11. Resultado esperado

Ao concluir o planejamento, apresente:

1. Resumo do projeto.
2. Objetivos.
3. Requisitos.
4. Escopo.
5. Tecnologias recomendadas.
6. Arquitetura proposta.
7. Considerações de segurança.
8. Etapas de implementação.
9. Critérios de conclusão.
10. Questões ainda pendentes.

O planejamento deve ser suficientemente claro para orientar o desenvolvimento sem limitar futuras melhorias.
